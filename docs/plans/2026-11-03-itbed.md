# 本地集成测试环境（IT bed）实现计划

> **给执行 agent：** 逐任务执行；终态全验证通过才算完成。**只动 sandbox 与测试设施，不改生产行为**；允许的非行为性小改仅限「地址/时钟可注入」。不部署。

**目标：** 本地跑起与生产**上层能力一致**的鱼：真实模型与 prompt、真实闸/合并/开窗/记忆/压缩逻辑，唯一差异是 **QQ 出口换成可观测日志**（faux NapCat），并能脚本化模拟群聊行为，用日志断言鱼的行为符合预期。生产数据零接触。

**架构：** `scripts/itbed/` 测试设施 + 独立 sandbox（专用 `YUGANG_HOME`，fresh db/media）+ faux 层三件（faux NapCat WS / faux 60s 新闻服务 / faux B 站 upstream）+ 场景驱动器（scenario JSON → 注入 → 断言）。鱼的进程即真实 `npm start`，只是 env 指向 sandbox 与 faux 端点。

## 全局约束

- 生产代码**零行为改动**；仅允许两类非行为性小改：①上游 base URL 可注入（bili-client/news-client 生产默认真实地址不变）②已有可注入面（时钟/定时器）的测试挂点
- 一切口径「上层一致」：prompt/、人格、闸与合并参数、模型角色表、工具面与生产相同；**物理上本地不存在的能力**（TTS 实例、SD WebUI、真实 NapCat）以 faux 等价体替代并声明差异
- 测试一切产物（db/media/日志/凭据缓存）只进 sandbox 目录；绝不读写生产 `var/` 与 macmini
- 凭据用本机已有 `config/auth.json`（真实模型调用）；无凭据的场景走 faux-model 档

## 与 macmini 的环境一致性（parity manifest）

一致性以**清单+校验脚本**保证（I0 产出，`scripts/itbed/parity/`）：
| 层 | 一致方式 |
|---|---|
| prompt/、src/、personas | 同 repo 同 commit（IT bed 起动时校验 git HEAD） |
| fish.config.json | 从 macmini 拉取一次落 `itbed/parity/fish.config.json`（含 ambient=120、compaction 阈值、watched 等），场景可覆盖（压缩时窗） |
| .env | 同样拉取（GROUPS/master/ONEBOT_TOKEN 换 faux 值），敏感项脱敏入 manifest |
| 模型角色表 | 本机 `config/models.json`（角色名一致即可，具体模型可不同——「兼容即可」） |
| voices/TTS | **声明差异**：本地无 GPT-SoVTS → IT 配置删除 voices（say_voice 按现行为报「无语音能力」），场景不测语音内容只测拒绝路径 |
| SD/gpt_image/search 等 | 真实可用则用；不可用场景不触碰（工具按需 deferred） |

## DAG

I0 → I2（启动器消费 parity）；I1 → I2；I2 → I3 → I4 → I5（I5 文档可随 I4 并行收尾）

## 任务

### I0：parity 清单与校验
**WritePaths：** `scripts/itbed/parity/`（manifest 生成脚本 + 拉取脚本走 home-mac-connect + 校验脚本）
- Produces：`parity-manifest.json`（macmini 的 fish.config 脱敏快照 + .env 键清单 + git HEAD 期望）；`check-parity.ts`（本地 vs manifest，输出差异表）；拉取脚本只读 macmini（用 home-mac-connect skill 的 connect.sh，凭据不入库）
- 验收：本地跑 check 有明确输出（一致/差异逐项）

### I1：faux NapCat WS 服务
**WritePaths：** `scripts/itbed/faux/napcat.ts`
- Produces：WS server（生产 OneBot 客户端反向连接的同一协议形态——先核对 src/qq/onebot.ts 的连接方向与消息封装，照实模拟）；出站→`outbound.jsonl`（含 send_group_msg 全参数）；注入 API（HTTP 或 IPC）：发群消息（可带 @鱼/@他人/回复引用/图片段/GIF 文件/合并转发/纯文本/`/` 指令/私聊）；心跳与 echo 响应；`get_group_list`/`get_group_member_info` 等鱼会拉的接口按固定名单应答
- 验收：真 fish 进程连上并完成一次收发（手动冒烟）

### I2：sandbox 启动器与 faux 上游
**WritePaths：** `scripts/itbed/launch.ts`、`scripts/itbed/faux/sixty.ts`、`scripts/itbed/faux/bili.ts`、`src/external/bili-client.ts`（仅 base URL 注入小改）、`src/external/news-client.ts`（同）
- Produces：`launch.ts`——组装 sandbox（`YUGANG_HOME=scripts/itbed/sandbox/<runId>`、fresh var、media fixtures、fish.config 覆盖层、.env 覆盖：ONEBOT_WS 指 faux NapCat、GROUPS/master 沿 parity），spawn `npm start`，SIGTERM 透传清理；faux 60s（:4399，/health、/v2/60s、/v2/weibo、/v2/baidu/hot 固定 fixture + 可脚本刷新）；faux B 站（popular/ranking/view/dm/reply/card 的 fixture 端点；bili-client 加 `BILI_BASE_URL` env 注入，缺省真实地址零变化）；news-client 的 60s 基址同理（RSS 源 IT 场景默认禁用——topic 配置只用 60s 源）
- 验收：一键起全套、鱼横幅连接成功、faux 出站日志有内容、退出干净

### I3：场景驱动器
**WritePaths：** `scripts/itbed/driver.ts`、`scripts/itbed/assert.ts`
- Produces：scenario JSON schema（`{ name, configOverride, steps:[{atMs, inject:{...napcat 事件}}, {awaitMs}], expects:[{kind: outbound|log|none, match, withinMs}] }`）；断言库：出站匹配（文本/提及/引用/媒体/条数/间隔≥6s/时段宵禁）、宿主日志匹配（gate 决定/换页/降级/审计行）；报告输出 pass/fail 明细 + 全程 outbound.jsonl 归档
- 时窗压缩：configOverride 直接用小值（closedMinutes=1/openMinutes=1/slots=启动后 1 分钟等），真实时钟不加速
- 验收：驱动器自带 dummy 场景自测通过

### I4：首批场景集（六组）
**WritePaths：** `scripts/itbed/scenarios/*.json`（或 .ts 生成器）
1. **legacy 基线**：限流 120s（压缩为 5s 覆盖）、10s 合并整组（A-B-A）、@ 必答挂引用、`/` 指令回执
2. **next 开窗**：closed 拦截 skip:next_pending、open free_pass、shard 合并多发送者、injection 背景板（无积压不注入）、宵禁 footer（时钟场景用配置把窗口卡进 0-9 点断言不可行→改为直接断言 footer 选择的纯函数已在单测覆盖，场景侧只测白天路径）、末条自言禁言（鱼发言后注入者再发?——用「鱼最后发言后驱动器不注入，下一窗断言无出站」近似）、配速 ≥6s
3. **评价与记忆**：`/评 好/差` 指向型与范围型（驱动器模拟主人）、`/记忆` 列表、批准后 memory section 出现（用宿主日志/读 sandbox db 断言）
4. **压缩**：小阈值触发换页（压缩配置 maxEntries=5）→ 断言剖面卡片段+机械尾巴在 sandbox db 的 pi.reset 里；faux-model 输出坏摘要→机械降级换页日志
5. **新闻播报**：faux 60s fixture → at=启动后 2 分钟 → 断言单条 say_words 出站（含来源链接、≤500 字）、幂等（再触发不出站）
6. **逛轮与分享**：slots=启动后 1 分钟 + browseMinutes 压缩 → faux bili fixture 候选 → worker 轮入库（db 断言）→ 开窗随机门（shareChance=1 强制开）→ 断言每窗最多 1 条外部分享、URL 为 canonical、claim 后不再 available
- 验收：`npm run itbed -- --all` 六组全绿（真实模型档；不稳定断言允许标记 flaky 隔离）

### I5：文档与脚本入口
**WritePaths：** `scripts/itbed/README.md`、`package.json`
- Produces：README（架构图、起法、写场景指南、faux 差异声明、parity 校验用法）；`npm run itbed [-- <scenario|all>]`
- 验收：新人按 README 能起一个场景

## 明确不做
- 不加速全局时钟（用压缩配置替代）；不做 GUI；不测 TTS 内容（无实例，只测拒绝路径）；不动 macmini 任何数据（parity 只读拉取）；不部署

## 新增测试授权说明
本计划整体即用户明确授权的测试建设（集成测试环境 + 场景断言），I1-I4 的设施与场景文件属授权范围；`src/` 侧仅 base URL 注入两处小改。
