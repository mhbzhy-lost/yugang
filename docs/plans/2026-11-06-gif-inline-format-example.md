# GIF 多帧 inline：鱼的实际输入格式（2026-11-06 定稿，已按此实现）

> 场景数据取自真实日志（搬史群 659976571）。`【image block】` 在实际输入里是
> 真正的 image block（JPEG base64，GIF 帧长边 ≤640px、静态图 ≤1280px）。
> 静默收图轮已退役（主人裁定）：GIF 只随下列场景进上下文，不再有专门轮次。

---

## 场景一：普通 @ 轮（群友发一张 GIF + 回复一张静态图）

```
群里有新消息啦。
> 消息起始
[m:844685635][回复了m:111784281][这条消息@了你] 遐蝶小姐的狗(2928390812): 看这个猫猫 [图片#1 inbound/1793333269955-d8adb4.gif ·动图4帧]
> 消息结束

[引用原文][m:111784281] 大肥鱼V4.1F(893311581)：「[图片#2 inbound/1793782479412-17b764.jpg]」

[图片#1 压缩图 ·动图4帧按时间顺序，同一张GIF]
[图片#2 压缩图]

[本轮要求] 只有 @ 你的这条消息明确要求你看/找一个 B 站视频时，才可以用 bili_hot 或 video；没被要求就别去看视频，也别分享视频链接。
```

block 序：GIF 的 4 帧（依时间序）→ 静态图 1 张。GIF 占 1 个编号、N 个 block；路径始终在标签里（draw ref 直接用）。

## 场景二：ambient 轮（自由拍 / open 窗 shard，直发 GIF 带双边收录标记）

```
群里有新消息啦。
> 消息起始
[m:1111528716] [有人@我](2627618651): [图片#1 inbound/1793784029351-186453.gif ·动图3帧值得收就用meme_add收它，不值得就不收]
> 消息结束

[图片#1 压缩图 ·动图3帧按时间顺序，同一张GIF]
```

随后 3 个 image block。**收不收当场判断**（双边标记避免一边倒鼓励收图）；不收就沉默，ambient 轮零出口合法。

## 场景三：meme_import 导入轮（inline 模式，GIF 抽 2 帧）

工具结果：

```
这一批登记了 5 张，图已按顺序附在下面，逐张看完逐张用 meme_add 收，别靠文件名猜内容：
meme-inbox/01.gif
meme-inbox/02.png
...
目录里还有 3 张，这一批处理完再调一次 meme_import，cursor 填 05.png
（清单顺序与附图顺序一一对应：静态图 1 张占 1 个图，01.gif 是动图占开头的 2 个图——按时间顺序的 2 帧）
```

block 序：01.gif 帧1 → 01.gif 帧2 → 02.png → …（附过的全部记「已见过」，meme_add 校验零改动）。

## 抽帧参数（已实现）

- `src/media/gif-frames.ts`：ffprobe 读帧数/时长 → 等距抽 `clamp(⌈秒⌉, 2, 4)` 帧（含首末；普通轮/shard 上限 4，导入轮 2），每帧长边 ≤640px JPEG q80
- 一个 GIF ≈ 2100 token（4 帧）——GIF 分辨率普遍不高、不承载大量文字，清晰度标准放低，省出的 token 换帧数（主人裁定）
- 抽帧失败降级首帧单张，不阻塞整轮
