# 决策：engagement=next 自由水群注入与发言策略（事件分片 + 周期机会）

- 日期：2026-11-03
- 状态：已决策
- 范围：engagement=next 的 open 窗注入口径与自由搭话（「自由水」——footer 里「随你自由发挥」、说不说话由模型定的闲聊形态）行为
- 性质：**本文档是审计决策记录，不是执行计划**。不含任务拆解、排期或改动步骤。

## 1. 背景与现场证据

**核心证据：模型注意力受当前触发输入影响。** 触发输入里出现什么，模型就把什么当作本轮的现场中心：把历史全量重塞进触发输入时，旧话会被当成新话接（复读、补回复已了结的话题）；只给增量时，注意力集中在真正新增的消息上。因此「历史不会每轮重复塞入」是本策略的第一性约束，其余设计都围绕它。

**现状机制（已存在，均保留）：**

- **lastSeenByModel 去重**：每会话记录最后一条进入模型输入的消息 arrivalSeq；背景板 / backlog / shard 注入先按上限取最近 N 条，再剔除已进过模型的，注入后推进到本轮实际注入集合的末条。重启懒定（标记为空＝全未读，不会饿死注入）。
- **open injection（开窗注入轮）**：closed → open 进入瞬间把本窗积压按背景板语义一轮注入（`ctx_engage_header + ctx_engage_line×N + ctx_engage_footer`），非必答、无 salvage，entry kind = `fish.engage_tick`（不写 fish.inbound、不进摘要与抽取）。
- **shardSeconds 分片（T14）**：open 窗内 free_pass（非 @）消息不进按发送者的 debounce 管线，改投 shard 收集器，每 `engage.shardSeconds` 一拍把全部发送者的新消息合成一轮 ambient 提交。
- **nudge-only（T8）**：连续全程零出口的 open 窗数达 `silenceThreshold` 档位后，积压为空时改提 nudge-only 轮（header + footer + nudge，无消息行）——这是唯一允许「无行注入」的轮，且仍遇忙放弃。
- **换页口径**：engage_tick 行计入换页阈值的条数与字符数，但不进摘要输入，原文行进换页尾巴（T12 裁定）。

## 2. 正式决策（采用策略）

1. **保留「事件分片 + 周期机会」结构**：closed → open 周期（`closedMinutes` / `openMinutes`）提供机会窗；窗内靠 shard 拍把新消息合流成轮提供事件机会；@ 消息照走 debounce burst 的 answer 轮，两轨互不干扰。
2. **open 首轮只给本窗新增积压**：窗口 = (lastCloseSeq, 开窗时刻] 的 recent 流水，排除 pending burst 内消息，过滤 `/` 指令与纯 GIF，超上限截最近 windowSize 条，再剔已读（lastSeenByModel）。已进过模型的消息绝不重放。
3. **后续轮只给上次输入后的新增消息**：shard 拍提交前按 `arrivalSeq > lastSeenByModel` 过滤（fresh），只注入真正的新增；提交等待期间新到的消息不算已读，仍归后续拍。
4. **没有新消息不提交常态空轮**：shard 空拍不提交（无收集即无轮）；injection 无积压且 nudge 档位为 0 时直接返回。常态下「无话可注 = 无轮可提」，不存在「没有新消息」的例行输入。
5. **沉默 nudge 仍只在阈值后触发**：档位由 `engageNext.silenceOf` 对比 `silenceThreshold` 现算（每窗现读热生效）；达阈值追加 nudge 文案、达 2×阈值换 `ctx_engage_nudge_2` 并把该窗积压窗口放宽到 windowRelaxCap；nudge-only 轮只在积压为空且档位到位时出现，不提前、不重试不补发。
6. **消息展示顺序采用最新到最早**：注入行按最新在上排列，模型可按行内 `[m:id]` 锚点向上回溯更早的上下文；`ctx_seen_note` 同位序照带，引导把上方旧行理解为已读过的历史而非孤立新话题。
7. **既有契约全部保留**：`ctx_seen_note`（每次注入轮都携带）、footer 宵禁二态（`ctx_engage_footer` / `ctx_engage_footer_night`）、quoteIds（＝当轮注入的 fresh 消息 id 集）、背压（忙不提交、整拍原子回收）、出站配速（sendPacingSeconds=6 的 outbox drain 间隔，全模式生效）、换页契约（engage_tick 计阈值不进摘要、原文行进换页尾巴）。

## 3. 不变量

- **上下文不变量**：任一环境轮的触发输入 = header + 本轮增量行 + footer（+ seen_note / 弹药段 / nudge）。历史不重复进触发输入；旧上下文经 `[m:id]` 锚点向上回溯与换页 transcript 重放可得。lastSeen 去重只作用于注入侧，不改变换页重放。
- **去重不变量**：lastSeenByModel 只推进到本轮实际注入 fresh 集合的 maxArrivalSeq（宁少勿答：推进过头会饿死后续注入）；只作用于背景板 / backlog / shard 与 @ 轮背景，@ 轮整组本体照常注入并推进。
- **引用不变量**：每轮 quoteIds = 当轮注入的 fresh 消息 id 集；出口 quoteMsgId 只能落在当轮窗口内的 `[m:id]` 上，跨窗引用无从发生；injection / shard 轮无强制引用。
- **背压不变量**：会话忙（在途轮 / 换页 / 收图）不提交，shard 拍到期忙则消息累积并入下一拍；提交失败整拍原子回收进收集器队首（保持到达序）；绝不丢已提交消息、绝不并发提交、绝不向 pi 的 steering 队列塞多条。唯一丢弃点是关窗收尾遇忙（丢弃并留日志，宁少勿答）。
- **成本不变量**：单轮输入有上界（header + ≤windowSize（放宽时 windowRelaxCap）行 + 固定尾件）；常态空轮为零；出站侧有 6 秒配速做总量护栏（3 分钟窗内出口物理上不可能刷屏）；nudge 是唯一额外轮型，受阈值与忙闸双重约束。

## 4. 明确拒绝的替代方案

**方案 A：每条消息一轮。**

- 成本：每轮都要付系统 prompt + 人格 + 工具 schema + transcript 的固定开销，一条一轮把固定开销按消息数线性放大；高频窗里同等信息量的 token 成本数倍于合并轮。
- 并发：与背压契约正面冲突——要么排队提交（消息延迟堆积，出口失去现场感），要么并发提交（破坏「绝不并发 / 不塞 steering」）；忙时放弃策略（宁少勿答）会造成大面积丢话。
- 引用窗口：quoteIds 按轮绑定，一条一轮时引用窗口退化为单条，模型接不了同拍里别人的话，`[m:id]` 的整窗上下文被拆碎。
- 换页：轮数暴增把换页阈值（条数 / 字符）顶满，engage_tick 行虽不进摘要却计入阈值并进换页尾巴，换页频率升高、尾巴里全是碎片噪音。
- 注意力：每轮单条迫使模型对每条消息都做一次「该不该接」的决策，把自由水变成逐条巡检；轮次间互相打断，注意力无法整窗组织。

**方案 B：每个 shard 拍都重复全量 50 条。**

- 成本：每拍固定全量 token，绝大多数是已读消息，重复计费零信息增量；窗内多拍叠加是平方级浪费。
- 并发：全量轮更长、在途时间更久，shard 退避（并入下一拍）频率随之上升，积压更易堆积——自我恶化。
- 引用窗口：quoteIds 每轮都罩住全量，窗口大而无当；模型可能引用几十条前的旧话当新话接，引用语义失真。
- 换页：每拍 50 行计入换页阈值，换页节奏被打穿；换页尾巴里出现成片复读，污染回放。
- 注意力：这正是现场证据反面的做法——旧消息反复占据触发输入中心位，模型把已路过的话当新话接（复读、补回复旧话题），`ctx_seen_note`「更早的都看过」的引导被自相矛盾的输入抵消。

**方案 C：常态输入「没有新消息」空轮。**

- 成本：零信息增量的固定开销轮，每窗每拍 × 白名单群数地烧 token，没有任何对应产出。
- 注意力：给模型持续制造「要不要说话」的强迫决策点，把「机会」变成「考勤」，与「机会不是强制发言、零出口合法」直接冲突；也把 nudge 的语义弄脏——沉默计数本意是「有话可说而没说」，常态空轮会把它稀释成系统陪跑。

## 5. 模型行为边界

- **机会不是强制发言**：injection / shard 轮均非必答、无 salvage、不掷语音义务，零出口合法；「说不说话你定」是窗口契约的一部分。
- **主动性来源**：新消息里可选的话头（含 `[m:id]` 引用与 @ 主人/特别关注的自由）、未兑现弹药（旧账弹药段的承诺/委托）、达阈值后的 nudge 文案。三者都只是候选，不是任务。
- **不靠伪造任务或强制回复**：不构造「必须回应」的假任务、不逐条巡检背景板、不把背景板当待办清单；header 文案已声明背景板「不构成需要你回应的任务，也不必补回复任何人」。

## 6. 旋钮与观测

**可调旋钮（engage 块，均热加载，非法值告警保留缺省）：**

| 旋钮 | 缺省 | 作用 |
| --- | --- | --- |
| `engage.shardSeconds` | 20（合法 5–120） | 分片节拍：每拍把窗内全部发送者新消息合并一轮。调大更省、出口更慢；调小接话更快、轮更多 |
| `engage.windowSize` | 20 | 常态积压注入上限：open 首轮最多行数，超限截最近 N |
| `engage.openMinutes` | 3 | 机会窗时长：窗内 shard 反复给机会；关窗结算沉默计数 |
| `engage.silenceThreshold` | 3（合法 1–50） | 连续全程零出口窗数达阈值才 nudge；2×阈值换 nudge_2 并放宽窗口 |

关联旋钮一句带过：`closedMinutes`（关窗时长）、`mentionContextSize`（@ 轮背景条数）、`windowRelaxCap`（放宽上限）、`sendPacingSeconds`（出站配速）、`engage.groups`（白名单，缺省空＝不进 next）。

**审计观测点：**

- **fish.engage_tick 的输入**：`[鱼缸] <chatKey> 搭话窗口 → open（积压 N 条）` 逐窗看积压规模；逐轮审计注入行应为增量——同一 `[m:id]` 不允许出现在两轮注入里。shard 背压留痕：`shard 在途退避，并入下一拍` / `shard 退避失败（已关窗），丢弃` / `搭话 shard 丢弃 N 条（…）`。
- **outbound 的 quote / quoteId**：出口消息的 quoteMsgId 应落在当轮 quoteIds 窗口内；出现引用轮外消息即违约。
- **零出口日志**：`零出口轮：模型没调 say_*` 仅 answer 轮记录；ambient / injection 轮零出口是合法静默（出口数 >0 才 noteExit，关窗结算沉默计数）；`nudge-only 轮提交（沉默递进档位 N）` 应只在阈值档位出现。
- **窗口 open / closed**：`[鱼缸] <chatKey> 搭话窗口 → open/closed` 相位日志；gate 侧 `-> shard:closed_drop` 说明 closed 态消息被正确丢弃不进 shard。

**验收口径**：注入轮输入中不出现本轮之前已注入过的 `[m:id]`；无新消息时无提交记录；nudge 文案只伴随达阈值档位；出口引用全部落在当轮窗口。

## 7. 非目标与回滚

- **不改 legacy**：engagement=legacy 的背景口径（恒 10 条、不去重）与全部既有行为零变化。
- **不改 @/回复必答**：answer 轮的必答、salvage、busy_reply 排队、引用语义均不动。
- **不改 worker/news**：E4 逛轮编排与 E7 新闻播报是独立管线，不掺入本策略。
- **实现面与回滚**：本决策的落地面只有两处——注入文案模板（prompt key）与注入行排列逻辑；若需回退，恢复这两处即可。状态机、去重标记、背压、配速、换页等既有机制不动；相位、lastCloseSeq、lastSeenByModel 均为内存态，重启自然归位，无数据迁移。
- **再次声明**：本文档是决策记录（为什么这样定、什么不能做、怎么观测），不是执行计划，不含任何实施步骤或排期。
