用本地显卡画一张图（出图后自动发出）：快、免费，但机器关机或排队超时会失败。
用户消息里出现 **qwen-image** 关键词（或明确要「Qwen 画的」）时改用 qwen_draw——那是另一条
自然语言管线；本工具只吃 danbooru tag，别把两种写法混着用。

当前使用的本地底模由主人在 `fish.config.json` 中通过 `drawBackend` 热配置控制（模型侧不指定也不感知具体底模名）。不同底模支持的模式与能力可能不同；若当前底模不支持某项模式或参数（如快速模式、改图、高清、双人同框、某模式下的 style 或双人构图参数），工具会在提交前直接返回明确拒绝原因，不会静默降级——按提示去掉对应参数或调整写法后重试即可。

画法两种：
- 从零画：不填 ref，按 prompt 画；ratio 选横图/方图/竖图，默认 3:4。
- 改图：填 ref，整张图按 prompt 重画。ref 认媒体目录内的 inbound/… 或 gen/…；
  改图沿用参考图比例，ratio 不生效。

非人物题材（风景/动物/物品）建议传 `fast: true`；有明确人物或双人互动需求时用默认单人从零画或双人 `characters`。

看不到图的内容就别猜原图长什么样。失败时把错误告诉用户、可以改描述重试，
不要换别的工具、也不要假装画好了。用户点名云端/在线画图时不在此处。

## 先定角色，再写画面

要画作品里的角色时，先查 tags（不传关键词会拿到平铺总表），把返回的 key 填进
character；双人填 characters[].character。本工具不列角色清单，也不要自己拼 key。

- 词表里有这个角色：把 key 填进 character，由当前后端自动挂载匹配的 LoRA（若当前底模没有对应 LoRA，则自动降级为注入该角色的基础外观 tag）并注入外观描述。prompt 只写动作、表情、构图、场景和服装，不要再写发色、瞳色、耳朵、头饰这些官方特征，也不要重复写角色 tag。
- 词表里没有的角色：可以把角色 tag 写进 prompt（先查 tags 拿准确写法和热度），外貌细节
  写清楚，并告诉用户没有这个角色的专属 LoRA，画的是接近的样子。
- 没点名具体角色：画面里的人就是普通人，外貌在 prompt 里写清楚。

官方服装不会自动注入。想要某套衣服，查该角色的条目，把服装段抄进 prompt；想随便穿就不抄。

## 画面与风格

prompt 写画面本身，用 danbooru tag 为主；普通 tag（cat_ears 之类）查 tags 词表拿准写法和热度。
**进本工具的全部文本（prompt 与 characters[].description）一律英文 tag/短语、逗号分隔**：本地模型只吃英文 tag 分布，
中文句子虽能被文本编码器编码，却条件化极弱且两句相近中文会互相吞并；写中文等于没写。
质量地板与负向词表都由工具后端内置、自动拼进采样，**prompt 只写画面内容，不要重复质量词，也不要在 prompt 写负向**。

用户明确说「自定义画图」时 prompt 传空字符串（内容交给角色词表/内置前缀）。
`style=<风格 key>` 挂全局画风 LoRA（不注入 tag，风格与角色 LoRA 权重由词表预设，模型不可调）；部分模式或底模不支持挂画风或没有该画风的对应 LoRA，遇拒时按回执提示去掉 `style` 或改用英文画风词描述。

不要在正向里写「不要什么」。
用户明确要其它特定画风时自己在 prompt 写风格词，或查风格 LoRA 词表有没有对应条目；
参考实测反例：soft gradient、soft volumetric lighting、light rays、
light particles 会把整图压成 pastel 洗白；detailed skin shading、subtle shadow 单独用出喷枪渐变皮肤
（欧美油腻感）。

用户明确要「高清大图 / 超级清楚 / 分辨率大点 / 当壁纸」时传 `hd: true`（更高分辨率输出，
明显更慢）；平时不传。

用户明确要「快一点 / 赶时间 / 随便画画」时传 `fast: true`（速度更快、细节略少）；平时不传。`fast` 不能与 `hd`、双人 `characters` 同时传。

## 双人

双人同框必须传 `characters`，恰好两项。每项写 description（英文 tag/短语，规则同 prompt）：挂了角色的只写动作、表情、服装；普通人写清外貌。人数不用写。命名角色默认传 `characters[].character`；仅当用户明确说「不挂 LoRA / 用 tag 直出」时才省去 `character` 键、自己在 description 写外观特征。
双人不支持顶层 `character`、`style`、`ref`；`hd` 是否可用取决于当前底模能力。

两人的 description 必须互相区分：姿态、朝向、所在侧（左/右、前/后）或服装至少一项不同，
并写明谁对谁做什么（A 牵着 B、B 靠在 A 肩上）。禁止两人写近乎相同的动作与朝向
（如都「坐着仰头看天」）——两人特征容易发生融合。
两人做同一件事时也要给各自不同的身体锚点：如一人盘腿坐左侧仰头、一人跪坐右侧扶膝。

双人只需选景别和间距，不传坐标或矩形尺寸；这两项只用于 `characters`（且部分底模不支持时会在预检拒绝）。

- framing 默认 normal：普通画面、中景或近景在 prompt 自然描述，人物动作和互动也可写入。
  用户没有明确要求远景时保持默认；近景用提示词表达。
- 用户明确要求远景、环境为主时传 framing: wide。此时 prompt 只写场景、环境与光照；
  两个人的动作、前后关系和互动写各自 description，避免公共描述再次生成一组人物。
  不额外手写 wide shot、very wide shot 或 distant small figures；远景效果由工具提供，
  不承诺人物缩到精确比例。
- spacing 默认 together：两人靠近，牵手、拥抱、依偎等接触动作保持这个选项。
  只有用户明确要求两人隔开且无身体接触动作时才传 apart；远景不等于两人彼此远离。
  默认时可省略这两个参数。

出图后宿主自动经 outbox 发出，不用再调 say_media 重发；只有回执说自动发送失败时，才用 say_media 把 gen/ 图补发。
一轮最多画一次；确认提交失败或预检被拒不消耗次数，提交状态不明时本轮不能重试。
